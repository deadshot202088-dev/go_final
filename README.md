# Планировщик задач (TODO-лист)

Веб сервер на go - аналог TODO-листа. Сервер хранит задачи в SQLite, отдаёт готовый
фронтенд из директории `web` и предоставляет REST API для добавления,
получения, редактирования, удаления и отметки задач как выполненных.
Задачи умеют повторяться по правилу (каждый день/год/неделю/месяц), и при
выполнении такой задачи она не удаляется, а переносится на следующую дату

## Выполненные задания со звёздочкой

- Порт сервера настраивается через переменную окружения `TODO_PORT`
- Путь к файлу бд настраивается через переменную окружения `TODO_DBFILE`
- Полная поддержка всех правил повторения в `NextDate`, включая `w` (дни
  недели) и `m` (дни/месяцы, включая отрицательные индексы `-1`/`-2` 
  последний и предпоследний день месяца)
- Поиск задач по подстроке в заголовке/комментарии и по конкретной дате
  (`GET /api/tasks?search=...`)
- Аутентификация по паролю: `POST /api/signin`, JWT токен в куке `token`,
  middleware проверка для `/api/task`, `/api/tasks`, `/api/task/done`
- Dockerfile для сборки и запуска сервера

## Запуск локально

```bash
go run .
```

По умолчанию сервер слушает порт `7540`, адрес в браузере -
`http://localhost:7540/`. Файл базы данных `scheduler.db` создаётся
автоматически в рабочей директории при первом запуске

Переменные окружения (все необязательные):

| Переменная      | Назначение                                   | По умолчанию     |
|-----------------|-----------------------------------------------|------------------|
| `TODO_PORT`     | порт веб-сервера                              | `7540`           |
| `TODO_DBFILE`   | путь к файлу базы данных SQLite               | `scheduler.db`   |
| `TODO_PASSWORD` | пароль для входа, если не задан, то аутентификация выключена | — |

Пример `.env` запуска:

```bash
TODO_PORT=7000 TODO_DBFILE=./data/scheduler.db TODO_PASSWORD=12345 go run .
```

Если `TODO_PASSWORD` задан, при открытии `http://localhost:7540/` сервер
потребует войти по адресу `/login.html`

## Запуск тестов

Тесты запускаются из корневой директории проекта **при запущенном сервере**:

```bash
go run . &
go test ./tests/...
```

Настройки тестов находятся в `tests/settings.go`:

- `Port`, `DBFile` - должны соответствовать значениям `TODO_PORT`/`TODO_DBFILE`,
  с которыми запущен сервер (либо переопределите их через те же переменные
  окружения при запуске тестов)
- `FullNextDate = true` включает проверку правил `w` и `m` в `TestNextDate`
  и `TestAddTask`
- `Search = true` - включает проверку поиска в `TestTasks`
- `Token`  JWT-токен, полученный от `/api/signin`, если сервер запущен с
  `TODO_PASSWORD` Если пароль не используется, оставьте пустым (`` ` ` ``)

## Сборка и запуск через Docker

Сборка образа:

```bash
docker build -t go_final_project .
```

Запуск контейнера с базой данных на хосте (сохраняется между перезапусками)
и с портом 7540:

```bash
docker run -d --name go_final_project \
  -p 7540:7540 \
  -v "$(pwd)/data:/app/data" \
  go_final_project
```

После запуска доступен в браузере по адресу
`http://localhost:7540/`, а файл `scheduler.db` появится в `./data` на хосте

Чтобы включить аутентификацию в контейнере, передайте пароль явно:

```bash
docker run -d --name go_final_project \
  -p 7540:7540 \
  -v "$(pwd)/data:/app/data" \
  -e TODO_PASSWORD=12345 \
  go_final_project
```
